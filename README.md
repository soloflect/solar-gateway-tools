# solar-gateway-tools

Tools for maintaining, archiving, translating, and analyzing logs from Solaflect solar tracking Gateway devices.

A Gateway is a Raspberry Pi 4B running the Solaflect Stratosphere software. The Gateway communicates with an STC (Solar Tracking Controller), a separate controller board containing a PIC32MX795F (S12L-80I/PF) microcontroller. The STC controls the two-axis solar tracker and is responsible for tracking the Sun.

This repository contains tools intended to run on a local Raspberry Pi or other Linux system that has SSH access to a Gateway.

## Log Archiving

`log-archiver.sh` periodically copies logs from a Gateway to a local system for long-term retention and analysis.

The Gateway logs currently archived include:

- Stratosphere Gateway log
- `syslog`
- `messages`
- `debug`
- `user.log`
- `daemon.log`
- `kern.log`
- `auth.log`

Both active and rotated logs are retained. Rotated logs are assigned sequential archive names, for example:

    stratosphere-000000001.log
    stratosphere-000000002.log
    stratosphere-000000003.log

and:

    syslog-000000001.log.gz
    syslog-000000002.log.gz

The original compression format is retained.

### Duplicate Detection

Gateway logs are periodically copied, so the same rotated log may be encountered multiple times before it disappears from the Gateway.

To prevent duplicate archives, `log-archiver.sh` calculates a SHA-256 hash for each complete log file. The hash is used as a duplicate lookup key. Each hash file records the name of the corresponding archived log.

This allows the archive to retain every unique log file without accumulating multiple copies of the same file.

### Gateway Configuration

The archiver also copies `stratosphere.conf` from the Gateway and extracts the Gateway's `local_cid`. Logs are stored under a directory associated with that CID.

The Gateway SSH user defaults to `pi`. The Gateway hostname or IP address is supplied on the command line.

Example:

    ./log-archiver.sh 192.168.1.207

An alternate SSH user can be specified with `-u`:

    ./log-archiver.sh -u pi 192.168.1.207

SSH public-key authentication is required so the archiver can access the Gateway without an interactive password.

## Scheduled Archiving

The archiver is intended to run periodically from `cron`.

Running the archiver at an interval that does not coincide with the Gateway's log rotation reduces unnecessary activity around rotation events.

For example:

    # m h  dom mon dow   command
    5 */10 *   *   *     /home/pi/solar-gateway-tools/log-archiver.sh 192.168.1.207 >/home/pi/solar-gateway-logs/log-archiver.cron.log 2>&1

This runs the archiver every 10 hours at five minutes past the hour.

## STC Status Records

The Stratosphere Gateway log contains status records generated by the STC.

A raw status record has the general form:

    Status(machines/<cid>/messages, <STC status data>)

The status data is a comma-separated record containing the STC's operating state, date and time, tracker positions, status and limit flags, electrical measurements, Sun sensor values, offsets, temperature, and other controller information.

For example:

    LOG,112798,25-115 09:52:41,23940,2594,23920,2594,0,0,0,0,1,1,1,0,0,1,1,1,0,0,275,979,9,0,0,0,79,152,181,315,0,0,0,5978,936,0,27,

These records are useful for examining the actual operating state of the tracker and for diagnosing tracking, stowing, actuator, electrical, and controller behavior.

## STC Log Translation

`translate-log.sh` translates STC status records into a human-readable tabular format.

The translator reads log input from STDIN by default and writes translated records to STDOUT. It can therefore be used as a normal Unix filter:

    ./translate-log.sh < stratosphere.log

Only STC status records are processed. Other Gateway log records are ignored.

### Reading a Gateway Log

A Gateway hostname or IP address can be supplied as the final command-line argument. The translator then obtains the log through SSH:

    ./translate-log.sh 192.168.1.207

The SSH user defaults to `pi` and can be changed with `-u`:

    ./translate-log.sh -u pi 192.168.1.207

### Following a Gateway Log

The `-f` option follows the remote log using `tail -F` over SSH:

    ./translate-log.sh -f 192.168.1.207

This provides a continuously updating display as new STC status records are written to the Gateway log.

### Repeating the Header

The `-H` option prints the column header after a specified number of translated records:

    ./translate-log.sh -f -H 25 192.168.1.207

The header is printed once when the translator starts and then every 25 translated records.

This is useful when following a long-running log because the column names remain available as the output scrolls.

## STC Time

The Gateway and STC currently use a local-time representation for the STC date/time.

The STC's use of local time is significant because the controller uses its clock when calculating the Sun's position. The relationship between the Gateway's time handling, the STC clock, UTC, and daylight-saving time is being investigated.

The tools in this repository are intended to make the recorded time behavior visible for analysis rather than assume that the STC's time representation is equivalent to UTC.

## Analysis

The archived logs provide a historical record of Gateway and STC operation.

Because the original Gateway logs are retained, the data can be examined at several levels:

- Gateway software behavior
- STC operating states
- Azimuth and elevation tracking
- Sun sensor values
- Wind-stow behavior
- Homing and calibration
- Electrical measurements
- Actuator operation
- Error and limit conditions
- Time and Sun-position calculations

The archive is intended to preserve the original log data so that additional decoders and analysis tools can be developed without losing the underlying records.

## Repository Structure

The repository contains tools used on a local Linux/Raspberry Pi system to collect and analyze data from Gateway devices.

The Gateway itself runs the Solaflect Stratosphere software. This project does not replace or modify Stratosphere; it provides separate tools for collecting, translating, and analyzing the data produced by the Gateway and STC.

## Requirements

The tools are intended for Linux systems and use standard utilities including:

- Bash
- SSH
- `awk`
- `sed`
- `grep`
- `date`
- `sha256sum`

SSH public-key authentication is required for operations that access a Gateway remotely.
